# flutter_adaptive_liquid_glass 0.2.0

This release expands the package to 21 UI capabilities and adds package-owned
frosted fallback controls, long-press actions and configurable interaction
feedback. iOS 26+ retains native Liquid Glass and its system tab bar; older iOS
and Android use the Flutter fallback. Light, dark and custom-color themes remain
supported.

## Install or upgrade

```yaml
dependencies:
  flutter_adaptive_liquid_glass: ^0.2.0
```

Run `flutter pub get` and rebuild the native application. A `^0.1.1` constraint
does not select 0.2.0 automatically. Existing 0.1.1 public surface, button,
navigation, selection, appearance and custom-color APIs remain available;
keep the application's `LiquidGlassAppearance` and `LiquidGlassNavigatorObserver`
setup. Long-press callbacks are optional, and controlled widgets still require
the application to accept edits by rebuilding with the new value.

Minimum requirements remain Flutter 3.41.2, Dart 3.11 and iOS 16. Development and
CI retain Flutter 3.41.9 / Dart 3.11.5; `native_liquid_glass` stays pinned to 0.3.1.
Native glass requires Xcode 26 or later. No new production dependency is added.

## What's included

- Controlled sliders, switches and steppers; activity and progress indicators;
  grouped toolbars; Flutter search editing and a controlled search scaffold.
- Date pickers with compact, inline and wheel styles; controlled sRGB color
  picking with optional alpha and HEX editing.
- Independent nested menus and typed alert/action-sheet, sheet and popover
  helpers, with keyboard constraints, nested-route visibility and anchor tracking.
- A 21-capability example catalog, plus the existing material and mixed-popup
  probes.
- Native slider editing callbacks retain their touch identity, so a late iOS 26
  editing-begin cannot reopen an already completed drag. Duplicate binding
  writes are ignored and accessibility adjustments use independent transactions.

Fallback sliders, switches, stepper buttons, date wheels and activity indicators
are drawn and operated by this package rather than Cupertino control widgets.
Date wheels reuse SDK localization resources for date order, labels and 12/24-hour
formatting. The Material inline calendar and Flutter text editors remain in use.
The existing frosted material is retained; no refraction shader or complex light
effect is added.

Date edits retain UTC/local representation, apply bounds to valid local minute
values and preserve repeated-hour occurrences. Regressions cover leap years,
month ends, full-hour and half-hour daylight-saving changes, external resets and
stale input after backgrounding or popup coverage.

## Long press and feedback

Buttons, icon buttons and `LiquidGlassAction` accept optional `onLongPress` and
`longPressSemanticLabel`. Long-only actions are supported. A recognized hold does
not also click on release; only stepper controls repeat. Menu triggers default to
tap and long press. Choose `LiquidGlassMenuTrigger.tap` or `.longPress` for an
explicit single-gesture policy; custom menu builders own their gestures.

```dart
const LiquidGlassThemeData(
  feedback: LiquidGlassFeedbackData(haptics: false, sound: false),
)
```

Both permissions default to enabled and can be changed independently. The flags
govern feedback requested by this package, including selection, long-press and
date-wheel feedback. They do **not** suppress feedback generated by native
system controls or the retained Material calendar. Reduced motion remains a
separate setting. Programmatic updates do not request interaction feedback;
stepper repetition is silent after its initial confirmation, and continuous
sliders signal endpoints rather than every intermediate value.

## Validation and known limits

Recorded local checks passed: root static analysis and 213 tests, example static
analysis and 6 tests, 32 picker tests in local, New York and Lord Howe time zones,
and 3 integration scenarios on each of Android 15, iOS 18.6 and iOS 27. Ordinary
example Android Debug APK and arm64 iOS simulator builds also passed. These are
local execution results; release CI and publication status are recorded separately.

Actual simulator input verified native button/capsule long presses and menu
reopening on iOS 27, plus fallback value controls, date scrolling and appearance
changes on iOS 18.6. The Android integration run used software rendering and does
not establish GPU performance.

The dedicated native XCTest uses a 0.2-second initial hold, slow system drag
and 0.2-second final hold. It checks four forward/reverse gestures, target values,
one start/end pair per drag and the final Flutter callback value. Two subsequent
stationary presses verify complete editing cycles without a value change. The release CI
adds a separate iOS 26 runtime gate for this scenario. Results and commands are
recorded in [release validation](https://github.com/starroyhq/flutter-adaptive-liquid-glass/blob/v0.2.0/doc/release-validation.md).

The six-operation native scenario passed on an actual iOS 26.5 runtime in
[release preparation CI](https://github.com/starroyhq/flutter-adaptive-liquid-glass/actions/runs/38082178380),
including the reversed stationary-press callbacks. Temporary diagnostic logging
was removed before delivery. The release's artifact-source run verifies the
final tagged commit separately.

The following acceptance checks remain open:

- A complete interactive control sweep on iOS 26. The dedicated CI gate uses
  an actual iOS 26 runtime for the native slider XCTest scenario, while broader
  local integration checks used iOS 18.6 and iOS 27.
- Very short desktop-injected native-slider input remains distinct from ordinary
  held input. No timing-based callback suppression is applied.
- Physical haptic strength and sound, full VoiceOver/TalkBack and keyboard/IME
  behavior, and device rendering, frame-time and power measurements.

Publishing this version does not mark those checks as passed. See the
[component coverage](https://github.com/starroyhq/flutter-adaptive-liquid-glass/blob/v0.2.0/doc/component-coverage.md),
[component validation](https://github.com/starroyhq/flutter-adaptive-liquid-glass/blob/v0.2.0/doc/component-validation.md)
and [interaction validation](https://github.com/starroyhq/flutter-adaptive-liquid-glass/blob/v0.2.0/doc/interaction-validation.md)
records for scope and evidence. The package remains MIT licensed.
